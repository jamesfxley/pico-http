# Standing deviations

Scope-wide suppressions require review under EN-00.5 and count against the
per-language ceiling under EN-00.6.

| Check | Scope | Rationale | Risk and mitigation | Approval | Review by |
|---|---|---|---|---|---|
| readability-magic-numbers | tests/ | EN-04.7, the exemption CXX-02.8 names explicitly. A literal size, offset or count in a test is the case under test, not a value shared with production code; hoisting it to a named constant moves the expected value away from the assertion that reads it. `CXX-13.2` keeps the tests under `tests/`, so one overlay there covers every module's tests. | A wrong expected value can agree with a defect in the implementation. Assertions compare behavior with the literal; review checks the expected value against the requirement or protocol, and other enabled checks remain active. | approved by the maintainer, 2026-10-29 | 2027-06-13 |
| misc-include-cleaner | tests/docs/ | EN-03.5. Each harness here and the `.inc` its document generates are one translation unit split across two files by design: the harness supplies the includes and stubs, the `.inc` holds the example. The check reads each file's includes against that file's own uses, so every include a harness makes for its example reads as unused, and keeping them is the only way the example compiles. | Unused includes can remain in a harness; each example is compiled and the harness-only scope keeps these includes out of the installed library. | approved by the maintainer, 2026-10-29 | 2027-06-13 |
| misc-use-internal-linkage | tests/docs/ | EN-03.5. The functions an example defines are a reader's code, with the external linkage a reader's code has; making them `static` or anonymous would show the reader a different program from the one they write, and an unused internal function is then a `-Wunused-function` error under the strict flags. | Unneeded external linkage can remain; harnesses compile examples without shipping their functions in the installed library. | approved by the maintainer, 2026-10-29 | 2027-06-13 |
| readability-magic-numbers | examples/ | CXX-02.8. The benchmark's literal sizes and durations are its parameters, not constants shared with anything else, so naming them adds an indirection without removing an unexplained value. | Unexplained sizes can enter the benchmark; named cases report their parameters and review checks them against the specification. | approved by the maintainer, 2026-10-29 | 2027-06-13 |
| modernize-avoid-c-arrays | examples/ | CXX-02.7. The benchmark reports over stdio with printf/snprintf into stack char buffers. The alternative — iostreams or std::format — pulls in allocation and code size that the firmware image is measured against by the footprint gate, so the rule's remedy costs the thing this tree exists to measure. | A raw reporting buffer can be overrun; bounded snprintf calls retain their size arguments and compiler diagnostics still apply. | approved by the maintainer, 2026-10-29 | 2027-06-13 |
| cppcoreguidelines-pro-bounds-array-to-pointer-decay | examples/ | CXX-02.7, same stdio reporting path as modernize-avoid-c-arrays above. | A pointer can lose its extent; reporting calls pass buffer capacities explicitly and the other bounds checks remain enabled. | approved by the maintainer, 2026-10-29 | 2027-06-13 |
| cppcoreguidelines-pro-type-vararg | examples/ | CXX-12.5, whose statement is scoped to varargs *on untrusted data*. Most of the benchmark's printf arguments are its own counters and timings. Two are request-derived — `/upload` reports `req.body.size()` and a checksum over the peer's body bytes — and both are integers passed to integer conversions, with no path by which a peer supplies or influences a format string. That is the ground the rule is relaxed on, not an absence of request-derived data. The library tree, which handles untrusted data structurally, keeps the rule on. | Format/type mismatches can corrupt output; compiler format warnings check literal formats and untrusted data is passed only as values. | approved by the maintainer, 2026-10-29 | 2027-06-13 |
| PLR0912 | examples/bench/bench.py | EN-04.7. A bench harness is a test tree: its branching is the device states under test, one arm per protocol reply and per failure mode, and collapsing them into a table would hide the very cases the harness exists to distinguish. The rule's remedy is decomposition, which here means splitting one readable sequence of device interactions across helpers that are only ever called once. The rule fires in pico-http's harness. | Complex bench logic can hide a wrong verdict; other Ruff checks still apply, device runs exercise the verdicts, and review checks each case against its criterion. | approved by the maintainer, 2026-10-29 | 2027-05-13 |
| C901 | examples/bench/bench.py | EN-04.7. A bench harness's functions are its numbered cases and the response reading beneath them, each one sequence whose branches are the replies and failure modes under test; the rule's remedy splits that sequence across helpers called once, so it no longer reads in the order the device sees it. It fires in pico-http's harness, most heavily in its results table. | Complex bench logic can hide a wrong verdict; other Ruff checks still apply, device runs exercise the verdicts, and review checks each case against its criterion. | approved by the maintainer, 2026-10-29 | 2027-05-13 |

It fires in pico-http's harness. | Complex bench logic can hide a wrong verdict; other Ruff checks still apply, device runs exercise the verdicts, and review checks each case against its criterion. | approved by the maintainer, 2026-10-29 | 2027-05-13 |
| PLR0913 | examples/bench/bench.py | EN-04.7. Signatures in pico-http's harness take more than five: `Response`, the record of one exchange, whose fields are its constructor's arguments; `connect_with_retry`, whose retry policy -- attempts, backoff and its cap -- is three defaulted parameters beside the address and timeout; and `one_shot`, one request's host, port, timeout, method, path, body, headers and attempts.
